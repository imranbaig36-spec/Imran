Symptom: Device DESKTOP-FB099 failed to complete Autopilot enrolment during the FinBridge programme migration on 2024-03-15. The enrolment was rejected immediately, zero of four mandatory configuration profiles were applied, and the device remained unmanaged with compliance state unknown. User FINBRIDGE\rthomas was unable to receive the managed desktop experience.

Cause: The verified root cause was a pre-existing active legacy MDM enrolment on DESKTOP-FB099 (enrolled manually on 2023-11-04) that was never retired before Autopilot was triggered. The Microsoft MDM service does not permit a second enrolment over an existing one and rejected the Autopilot flow with error 0x80180014. The absence of a pre-migration runbook check meant the technician proceeded directly to triggering Autopilot on the live, previously-enrolled OS without clearing the legacy record first.

Scope: The incident directly affected a single device (DESKTOP-FB099) and one user (FINBRIDGE\rthomas). However, the underlying process gap affects all devices in the migration queue that carry legacy manual MDM enrolments pre-dating the Autopilot programme. Blast radius across the estate is unknown until a pre-migration audit is completed.

Workaround: Delete the legacy MDM enrolment record from Intune (Devices → All devices → locate DESKTOP-FB099 record with enrolment date 2023-11-04 and source Manual/Legacy → Delete → wait 5–10 minutes). Then wipe the device from Intune (Devices → All devices → Wipe, leave enrolment state retention unchecked) and complete Autopilot OOBE as FINBRIDGE\rthomas. Verify enrolment source shows Autopilot and all 4 profiles show Succeeded before returning the device to the user.

Permanent fix: Conduct an immediate pre-migration estate audit — export all devices from Intune filtered by enrolment source Manual and enrolment date before the Autopilot programme start date, cross-reference against the migration queue, and schedule a maintenance window for each matched device to delete the legacy record and wipe before Autopilot is triggered. Update the Autopilot migration runbook with a mandatory Gate 0 pre-flight check requiring technicians to confirm no existing MDM enrolment record exists in Intune before proceeding. Create a dynamic Azure AD device group to surface legacy-enrolled devices as an ongoing standing filter for all future migration batches.

How to spot it: MDM diagnostic export on the failing device will show EnrolmentState: Failed and ErrorCode: 0x80180014 (The device is already enrolled in MDM). A secondary error 0x80070005 (Access Denied) will appear in PolicyManager with ProfilesApplied: 0 and a named FailedProfile. DeviceInfo will confirm MDMEnrolled: Yes (previous enrolment) and EnrolmentSource: Legacy. ComplianceEngine will show EvaluationResult: Could not evaluate. Network, licensing, TPM, Secure Boot, and Azure AD join will all show as healthy — these are not the cause. The sole blocking condition is the pre-existing enrolment record.
